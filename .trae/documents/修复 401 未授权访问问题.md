## 问题分析

从日志可以看到所有 API 都返回 **401 未授权访问**：
- `POST /api/user/update 401`
- `POST /api/user/change-password 401`

### 根本原因

1. **服务端 Supabase 客户端配置问题**
   - `createServerClient()` 使用了 `persistSession: false`
   - 这意味着服务端无法获取用户的 session
   - `supabase.auth.getUser()` 返回 null

2. **API 路由中的 session 处理**
   - 虽然使用了 `@supabase/ssr` 的 `createServerClient`
   - 但 cookie 没有正确配置，无法读取浏览器中的 session

### 修复方案

1. **修复服务端 Supabase 客户端**
   - 修改 `lib/supabase/server.ts`
   - 添加 cookie 支持，使其能够读取浏览器 session

2. **或者使用 Admin Client**
   - 使用 `createAdminClient()` 绕过 session 验证
   - 通过用户 ID 直接操作数据库
   - 前端传递 userId 到 API

### 推荐方案

**方案1：修复 cookie 配置（推荐）**
- 修改 API 路由，正确配置 cookie
- 保持现有的认证流程

**方案2：使用 Admin Client（备选）**
- 前端从 useAuth 获取 user.id
- 调用 API 时传递 userId
- API 使用 Admin Client 验证用户存在后操作

2. 更新所有 API 路由使用正确的客户端
3. 验证修复效果
