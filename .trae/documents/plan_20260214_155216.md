
# 修复 Next.js 错误和签到问题

## 问题分析

通过查看代码，发现以下关键问题：

### 1. **API 认证方式不一致**
- `/api/user/stats/update` 使用 Supabase SSR 从 cookies 获取用户（`supabase.auth.getUser()`）
- `/api/checkin` 和 `/api/user/me` 使用查询参数 `userId` 或自定义 header
- **问题**：前端调用这些 API 时认证方式不统一，导致 401 未授权错误

### 2. **签到问题**
- 签到 API 在检查今日已签到时返回 400 错误
- 前端显示 "今日已签到" 但可能用户实际未签到

### 3. **获取用户信息 API 问题**
- `/api/user/me` 期望 `x-user-email` header，但前端调用时通过查询参数传递 `userId`

## 修复计划

### 第一步：统一 API 认证方式
- 修改 `/api/user/me` 支持从查询参数或 Supabase 会话获取用户
- 修改 `/api/user/stats/update` 也支持 `userId` 查询参数作为备选方案
- 修改 `/api/checkin` 也支持 Supabase 会话认证

### 第二步：修复签到问题
- 优化签到 API 的错误处理
- 确保签到成功后正确更新积分

### 第三步：修复错误处理
- 优化前端的错误处理逻辑，提供更好的用户体验

## 需要修改的文件
1. `app/api/user/me/route.ts` - 支持多种认证方式
2. `app/api/user/stats/update/route.ts` - 支持 userId 参数
3. `app/api/checkin/route.ts` - 支持 Supabase 会话认证
4. `app/checkin/page.tsx` - 优化错误处理
5. `lib/user-stats.ts` - 优化错误处理
