## 修复 verification_codes 表权限问题

### 问题
`permission denied for table verification_codes` - 服务端使用 `service_role` 密钥，但 RLS 策略只允许 `anon` 角色访问

### 解决方案

#### 方案 1: 为 service_role 添加 RLS 策略（推荐）
为 `service_role` 角色添加绕过 RLS 的策略，允许服务端完全访问

#### 方案 2: 禁用 RLS（不推荐）
直接禁用 RLS，但这会降低安全性

#### 方案 3: 修改服务端使用 anon 密钥（不推荐）
服务端改用 `anon` 密钥，但这会失去服务端应有的权限

### 实施步骤

**推荐方案 1**：

1. 更新 SQL 迁移文件，为 `service_role` 添加策略
2. 在 Supabase SQL Editor 中执行更新后的 SQL
3. 重新测试验证码发送功能

### SQL 修改内容

```sql
-- 为 service_role 添加绕过 RLS 的策略
CREATE POLICY "Allow service role bypass RLS" ON verification_codes
    FOR ALL TO service_role
    USING (true)
    WITH CHECK (true);
```
