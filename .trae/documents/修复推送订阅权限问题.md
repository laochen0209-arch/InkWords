## 问题分析

错误 `permission denied for table push_subscriptions` 说明 RLS 策略仍然没有正确生效。即使用户执行了 SQL，但由于 `upsert` 操作涉及 INSERT 和 UPDATE，而策略配置可能不完整。

## 解决方案

最简单的修复方案是：**在服务器端 API 中使用 Service Role Key 绕过 RLS 限制**。

这是安全的，因为：

1. 这是服务器端代码，用户无法直接访问
2. 我们已经在代码中验证了用户身份（从 Cookie 获取）
3. 使用 Service Role Key 是服务器端操作的常见做法

## 需要修改的文件

1. `app/api/notifications/subscribe/route.ts` - 使用 `createAdminClient` 替代 `@supabase/ssr` 的客户端

## 修改内容

将：

```typescript
import { createServerClient } from '@supabase/ssr';
const supabase = createServerClient(...)
```

改为：

```typescript
import { createAdminClient } from '@/lib/supabase/server';
const supabase = createAdminClient();
```

同时保留用户身份验证逻辑（从 Cookie 获取用户）。
