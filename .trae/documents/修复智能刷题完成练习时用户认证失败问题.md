## 问题分析

从日志可以看到：

1. `getUser 失败: AuthSessionMissingError` - Supabase 客户端实例没有会话
2. `所有方式都无法获取用户ID` - 三种方式都失败了
3. 但用户实际上已登录（截图显示有用户界面）

## 根本原因

`ExamContent.tsx` 使用的 `supabase` 实例是全局单例，但这个实例在某些情况下可能没有正确恢复会话状态。

虽然 `useAuth()` 中的 `authUser` 可能是有值的（因为 AuthContext 正确获取了用户），但 `handlePracticeComplete` 函数没有优先使用它。

## 修复方案

修改 `handlePracticeComplete` 函数：

1. **优先使用** **`authUser`**：直接从 `useAuth()` 获取的 `authUser` 读取用户ID
2. **作为备选使用 Supabase**：如果 `authUser` 为空，再尝试从 Supabase 获取
3. **最后尝试 LocalStorage**：兜底方案

## 具体修改

**文件**: `app/practice/drill/ExamContent.tsx`

修改 `handlePracticeComplete` 函数的用户获取逻辑：

```typescript
// 第零步：优先使用 auth context 中的用户（最可靠）
let userId = authUser?.id;
console.log('[Practice] 方式0 authContext:', userId ? '成功' : '失败');

// 第一步：如果 auth context 没有，尝试从 Session 获取
if (!userId) {
  const { data: { session } } = await supabase.auth.getSession();
  userId = session?.user?.id;
  ...
}
```

这样即使 Supabase 客户端实例有问题，也能通过 React Context 获取到用户。
