## 前后端数据对接检查报告

### 1. 数据库表结构

**mock_exams 表：**
- `id`: 主键
- `exam_type`: 考试类型 (IELTS, TOEFL等)
- `sections`: JSON 格式，包含完整的 section 结构
- `questions`: JSON 格式（旧格式，兼容用）
- `rewritten_content`: 文章内容（旧格式）
- `created_at` / `updated_at`: 时间戳

**ExamResult 表：**
- `userId`: 用户ID
- `examType`: 考试类型
- `score`: 得分
- `maxScore`: 满分
- `details`: JSON 格式的详细结果
- `aiFeedback`: AI评语

### 2. 前端数据获取 (ExamContent.tsx)

**获取考试数据：**
```typescript
const { data, error } = await supabase
  .from("mock_exams")
  .select("*")
  .eq("exam_type", currentType)
  .range(randomOffset, randomOffset)
  .single();
```

**数据处理：**
- 解析 `sections` JSON 字段
- 兼容旧格式 `questions` 字段
- 为每个 question 生成唯一 id

### 3. 后端提交接口 (submit/route.ts)

**接收数据：**
- `userId`: 用户ID
- `examData`: 考试数据（包含 sections 和 questions）
- `userAnswers`: 用户答案

**评分逻辑：**
- 客观题：自动评分（选择题、判断题、填空题）
- 主观题：调用 DeepSeek AI API 评分

**数据存储：**
- 保存到 `exam_results` 表
- 同时记录到 `practice_logs` 表（向后兼容）

### 4. 发现的问题

**问题1：听力播放无反应**
- 原因：`transcript` 字段可能为空
- 建议：检查数据库中 `sections` 字段的 `transcript` 是否有内容

**问题2：字段名不匹配**
- 前端使用 `exam_type`（snake_case）
- Prisma schema 使用 `examType`（camelCase）但映射到 `exam_type`
- ✅ 已通过 `@map` 解决

**问题3：旧数据兼容**
- 代码中有处理旧格式 `questions` 的逻辑
- 如果 `sections` 为空，会尝试从 `questions` 转换

### 5. 数据流验证

```
用户点击考试类型
    ↓
前端: 从 URL 获取 type 参数
    ↓
前端: 调用 supabase.from("mock_exams").select()
    ↓
后端: 返回考试数据
    ↓
前端: 解析 sections JSON，渲染题目
    ↓
用户答题
    ↓
前端: 收集 userAnswers
    ↓
用户提交
    ↓
前端: POST /api/practice/submit
    ↓
后端: 评分并保存到 exam_results
```

### 6. 建议检查项

1. **数据库中是否有数据：**
   ```sql
   SELECT exam_type, COUNT(*) FROM mock_exams GROUP BY exam_type;
   ```

2. **sections 字段格式是否正确：**
   ```sql
   SELECT sections FROM mock_exams WHERE exam_type = 'IELTS' LIMIT 1;
   ```

3. **transcript 字段是否有内容：**
   检查 sections 中 listening 类型的 transcript 字段

4. **网络请求是否正常：**
   打开浏览器控制台查看 Network 标签
